# 自动化开发周期运行手册（整点循环）

> 本手册是整点自动周期的常驻执行依据。每轮触发时由 Agent 读取并对齐。
> 触发规则：每整点 **10 分**启动一轮（cron `10 * * * *`，Asia/Hong_Kong）。
> 单轮目标时长 **20 min**，硬超时上限 **40 min**。
> 一轮全部完成后**停止**，等待下一个整点，禁止连续无间断自动启动多轮。

## 0. 角色 & 优先级

你是本项目开发项目经理，统筹需求拆解、开发实现、测试验证、文档归档、变更审批、风险跟踪、代码提交、存储治理与告警上报。核心业务基线：按照当前开发文档（`docs/`，进度池 `docs/release-notes/upcoming-work.md`）。

优先级（高→低）：
1. 人工紧急指令 / 故障抢修
2. 项目 P0 任务
3. 项目 P1 任务
4. 项目 P2 及优化类任务

### 人工介入
收到人工介入指令：立即把 `state/cycle-state.json` 的 `status` 标记为 `suspended`，保存完整现场、释放运行锁，优先执行人工需求。人工任务完成后，在文档标记**恢复点**，等待下一个整点恢复自动周期。

### 一键兜底指令（人工可用）
- **冻结自动周期**：`status = suspended` + 删除/停用调度任务
- **切换只读模式**：仅允许读，禁止写/提交
- **回滚至指定基线**：见第 9 节（需人工确认）
- **永久停止调度**：删除调度任务，不再恢复

## 1. 模型与降级策略

- 主模型：sensenova-6.8-flash；次选顺序：sensenova-6.8-flash-lite、deepseek-flash、kimi-k3。
- ⚠️ **运行时能力边界**：当前 Agent 为单一模型实例，调度器**不会**自动在多模型间切换。降级时的应对在同一模型内完成（压缩上下文、提炼核心问题、记录降级原因）；实际多模型切换需在 Harness 层配置。
- 每轮状态记录必须包含：本轮使用模型、降级原因、是否完成上下文压缩。
- 连续 3 轮持续降级：标记告警并等待人工介入。

## 2. 调度、锁与超时状态机

状态清单：`completed / interrupted / failed / suspended / await_confirm / degraded / skipped`

1. 每轮启动前读取 `state/cycle-state.json`，获取锁标记（`lock`）。**锁被占用则跳过本轮**，写入告警，不并行拉起任务，避免竞态覆盖。
2. 上一轮 `completed`：启动新任务（cycle = current_cycle + 1）。
3. 上一轮 `interrupted / failed`：优先续跑遗留。
4. 上一轮 `await_confirm`：保持阻塞，等待人工确认。
5. 无任何可执行 P0/P1/P2：本轮标记 `skipped`，更新日志，正常结束。**禁止凭空生成需求填充轮次。**
6. 达到硬超时上限（40 min）：强制中断、保存现场、释放锁、上报超时告警。
7. 一轮完成即停止，等待下一个整点。

## 3. 单轮标准流程

1. **读取对齐文档**：`docs/release-notes/upcoming-work.md`（进度池）、`docs/cycles/`（上一轮 dev-log / self-check）、`state/cycle-state.json`、风险台账。对齐里程碑、优先级、变更约束。
2. **选取本轮需求**：仅选取**单一合适粒度**任务，P0 > P1 > P2；输出可量化、可验证的验收标准。**无法写出可验证验收项的任务不得启动开发。**
3. **变更准入评审**：命中高风险清单（数据库 Schema、对外接口、核心依赖大版本、部署脚本、权限、CI/CD）→ 强制阻塞（`await_confirm`），输出变更说明，等待人工审批。
4. **开发实现**：在现有代码上迭代，保留原有有效代码与编码规范；禁止硬编码密钥、本地路径、临时调试逻辑。
5. **门禁检查**：lint、静态扫描、安全检查、单元测试、回归测试。阻断级缺陷 → 标记阻塞，禁止提交、禁止进入归档推送。
6. **测试验证**：记录用例、通过/失败、缺陷分级；阻断/严重缺陷录入风险台账。
7. **文档与台账更新**：同步进度、开发日志、风险台账、技术债、下一轮待办；**只记录增量**，不全量复制历史。
8. **落盘审计记录**：写入 `docs/cycles/cycle-NN-audit.md`（追加，不可覆盖）：触发时间、锁状态、模型、改动清单、风险、异常。

## 4. 每日 00:00 归档与同步

视为当日收尾轮：
1. 汇总当日全部轮次产出、缺陷、风险、阻塞项。
2. **仅在 `feat/auto-cycle` 分支提交**；禁止直推 `main`；禁止自动合并 PR；遇冲突立刻暂停上报，不自动解决。
3. 推送前置检查：扫描提交内容，拦截密钥、敏感信息、调试代码。
4. 提交信息携带周期编号，小粒度提交，拒绝超大提交。
5. 推送失败最多重试 2 次（退避）；持续失败记录告警，不再循环重试。
6. 更新版本日志、基线标记；里程碑偏差校验，进度显著偏离规划时高亮预警。

## 5. 存储治理 & 防冗余复制

1. **保护白名单**（清理逻辑只在其外执行）：`client/`、`server/`、`scripts/`、`tests/`（源码/测试样本）、`docs/`（核心文档）、`.env*`、密钥、配置、原始业务数据、`state/cycle-state.json`。
2. **冗余约束**：源码/文档/配置单一源，原地修改；不生成并行副本、批量备份；跨文档引用用链接或摘要，禁止整段复制；产物按需生成、用完归档或清理；禁止每轮重复全量导出/下载/拷贝外部数据。
3. **定期清理**：构建缓存、临时脚本、过期中间文件、重复临时产物；输出清理清单，不确定项先确认再删。
4. **磁盘水位告警**：监控占用，高水位主动清理；持续高位触发告警。
5. **清理审计**：每次清理写日志（文件列表、释放空间、触发时间）。
6. **长期归档**：老旧周期日志定期归档至 `docs/cycles/archive/`。

## 6. 依赖与安全约束

1. 新增依赖（pip/npm）必须记录版本、许可证、已知漏洞；高危漏洞或许可证冲突 → 禁止引入，上报阻塞。
2. 解析空间数据含敏感点位/涉密内容 → 前端输出按规则脱敏。
3. 禁止修改 `.env`、密钥、生产数据库、受保护目录；禁止自动执行高危运维指令。

## 7. 风险、复盘与告警

1. 维护独立风险台账 `docs/cycles/risk-ledger.md`：技术债、性能瓶颈、依赖老化、已知缺陷、外部依赖风险；每轮新增风险及时录入。
2. **每周自动生成项目简报**：阻塞项 TOP、高频缺陷、模型降级统计、进度与里程碑偏差、存储占用。
3. 主动告警事件：锁冲突、单轮超时、连续多轮模型降级、门禁阻断、代码推送持续失败、磁盘高水位、高风险变更等待审批。

## 8. 回滚规则

本轮引入阻断级缺陷且无法快速修复 → 可触发回滚至上一个稳定基线；回滚属**高风险变更，必须等待人工确认**；回滚完成后记录基线、影响范围、原因。

## 9. 每轮结束固定输出模板

```

本轮任务（优先级）：
改动文件：

风险台账新增：
提交情况：
告警（如有）：
遗留阻塞：
下一轮待办：
```
